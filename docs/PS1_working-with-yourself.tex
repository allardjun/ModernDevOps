\subsection{A. Make a repository}\label{a.-make-a-repository}

\begin{enumerate}
\def\labelenumi{\roman{enumi}.}
\item
  Go to \href{https://github.com/new}{github.com/new}. Give it a name
  like \texttt{my-first-repo}. Keep it \textbf{Private}.
\item
  Tick \textbf{Add a README file}.
\item
  In the \textbf{Add .gitignore} dropdown, choose the template for
  whatever language you actually work in --- Python, R, Julia, MATLAB.
  Then click \textbf{Create repository}.
\item
  (Optional) Open the \texttt{.gitignore} it made for you and inspect
  it.
\item
  Click \texttt{README.md}, click the pencil icon, delete what is there,
  and paste this in its place:

\begin{Shaded}
\begin{Highlighting}[]
\FunctionTok{\# Rotation project}

\FunctionTok{\#\# Results so far}

\NormalTok{Nothing yet.}

\FunctionTok{\#\# Conditions}

\PreprocessorTok{|}\NormalTok{ Condition }\PreprocessorTok{|}\NormalTok{ Temperature }\PreprocessorTok{|}
\PreprocessorTok{|}\NormalTok{ control }\PreprocessorTok{|}\NormalTok{ 25 C }\PreprocessorTok{|}
\PreprocessorTok{|}\NormalTok{ heat shock }\PreprocessorTok{|}\NormalTok{ 42 C }\PreprocessorTok{|}

\FunctionTok{\#\# Overview}

\NormalTok{Measuring how fast the reporter turns over under heat stress.}
\end{Highlighting}
\end{Shaded}

  Commit it.
\end{enumerate}

\subsection{B. Editing and committing}\label{b.-editing-and-committing}

Perform each of the following edits, with each one being a separate
commit, with a semantic commit message. Use the \textbf{Preview} tab in
the editor as you go, so you can see what your Markdown actually renders
as.

\begin{enumerate}
\def\labelenumi{\roman{enumi}.}
\item
  Add a column to the table that records a rate \(k\).
\item
  But the conditions table in \texttt{README.md} does not render
  properly. It comes out as one long line with pipes in it, instead of a
  table. Fix it.

  \emph{A Markdown table needs a row of dashes under its header,
  separating the header from the body. Without it, the whole thing is
  just a paragraph that happens to contain \texttt{\textbar{}}
  characters.}
\item
  Add a \textbf{Data} section to \texttt{README.md}, saying where the
  large files for this project live --- a Dropbox folder, a Google
  Drive, a server --- and why they are not in this repository.
\item
  Put the sections in a more standard order: Put \textbf{Overview} at
  the top.
\end{enumerate}

\subsection{C. Read your own history}\label{c.-read-your-own-history}

\begin{enumerate}
\def\labelenumi{\roman{enumi}.}
\item
  Go to your repository's front page and click on the commit count ---
  the little clock icon with a number next to it.
\item
  Six months from now you want the commit where you recorded \(k\). Can
  you find it from the messages alone, \textbf{without opening a single
  commit}?
\end{enumerate}

\subsection{D. Optional: the hash that cannot cite
itself}\label{d.-optional-the-hash-that-cannot-cite-itself}

Every commit has a hash --- the string like \texttt{e4f19a2} beside it
in the list. It is a fingerprint of everything in the project at that
moment. It is how the three places in the lecture --- data, code,
manuscript --- each record which version of the others they go with.

\begin{enumerate}
\def\labelenumi{\roman{enumi}.}
\item
  Copy the hash of your most recent commit. Add a line to
  \texttt{README.md} reading \textbf{This version: \texttt{e4f19a2}},
  with your own hash, and commit it.

  Your README now cites the version before it. A figure caption in a
  manuscript does exactly this, which is what lets you regenerate that
  figure years later.
\item
  Are you able to make the \texttt{README.md} state the current commit
  hash? \emph{Hint: do not try for too long.}
\end{enumerate}
